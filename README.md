# acrust

English | [日本語](README-ja.md)

A competitive programming CLI **built only for AtCoder and Rust**.

```console
$ cargo install acrust   # or: cargo binstall acrust, for a prebuilt binary
$ acrust init            # put the repository under acrust
$ acrust env update      # match AtCoder's judge environment
$ acrust login           # paste the session cookie from your browser
$ acrust new abc474
$ acrust test a
$ acrust submit a
```

## Commands

| Command | What it does |
|---|---|
| `acrust init` | Generate `.acrust/` and `rust-toolchain.toml` |
| `acrust login` / `logout` | Get or discard the AtCoder session |
| `acrust status` | Where the config is, which judge environment is in use, whether you are logged in, and what needs doing |
| `acrust new <contest>` | Create the package and fetch the samples |
| `acrust fetch [contest]` | Fetch the samples again |
| `acrust test [problem]` | Build and run the sample tests |
| `acrust run [problem]` | Run with stdin passed straight through |
| `acrust submit [problem]` | Test, then submit and follow the result |
| `acrust copy [problem]` | Copy the solution to the clipboard |
| `acrust open [problem]` | Open the problem in a browser |
| `acrust env update` | Regenerate the crates, `Cargo.lock`, `edition` and rustc from the judge environment |
| `acrust migrate` | Convert a cargo-compete repository to the acrust layout |

For `test` / `run` / `submit` / `copy` the problem is optional: left off, they act on the one you
edited last. `submit` confirms first, since a submission cannot be taken back.

## Logging in

acrust imports the session cookie your browser already holds.

Log in with your browser, then open DevTools -> Application (Storage in Safari) -> Cookies ->
`https://atcoder.jp` and paste the Value of `REVEL_SESSION`.

## Layout

```
atcoder-rust/
├── .acrust/
│   ├── config.toml               # settings
│   └── template/
│       ├── main.rs               # copied to src/bin/*.rs for every new problem
│       ├── dependencies.toml     # generated by env update
│       ├── Cargo.lock            # fetched by env update
│       └── copy/                 # copied into each package as it is
├── rust-toolchain.toml           # pinned to the judge's rustc
└── abc474/
    ├── Cargo.toml
    ├── src/bin/{a..g}.rs
    └── testcases/{a..g}.toml
```

Everything under `.acrust/` is yours to edit:

- **`template/main.rs`** — the starting point for every problem. Put your usual `use` lines, macros
  and input boilerplate here.
- **`template/copy/`** — copied into each package verbatim. `.vscode/launch.json` ships here; add
  anything else a package should start with.
- **`template/dependencies.toml`** — the crates a package gets. `env update` regenerates it, but
  shows you the diff before writing, so trimming it by hand survives as a decision you re-confirm.
- **`config.toml`** — where packages go, the profile and parallelism `test` builds with,
  `timeout-margin`, whether a problem may be inferred, and which language `submit` picks.

Credentials live outside the repository: `~/.local/share/acrust/session.json` (mode 0600, overridden
by `ACRUST_SESSION_FILE`) and the cache in `~/.cache/acrust/`.

## Submitting

```console
$ acrust submit c
  → abc474 c (src/bin/c.rs)
✓ 2/2 AC
  language:      Rust (rustc 1.89.0) (id=6088)
✓ submitted  WJ  https://atcoder.jp/contests/abc474/submissions/12345678
  AC   5s           312 ms / 4.2 MB
```

The sample tests run first (`-f` skips them), and the verdict is followed afterwards (`--no-watch`
turns that off). What is sent is always `src/bin/{alias}.rs` as it stands.

> **A contest that has ended cannot be submitted to from the command line.** Use `acrust copy` for
> those.

`acrust copy` puts the solution on the clipboard byte for byte and prints where to paste it.

```console
$ acrust copy c
✓ copied (5 lines / 86 bytes, via pbcopy)

Paste it here to submit:
  https://atcoder.jp/contests/abc418/tasks/abc418_c
```

## Migrating from cargo-compete

`acrust migrate` converts a cargo-compete repository once. It is a dry run until you pass `--write`,
wants a clean working tree (`--allow-dirty` overrides), and verifies that the conversion round-trips
before writing anything — one mismatch and it stops having written nothing.

## Development

```console
$ cargo fmt --all --check
$ cargo clippy --all-targets --all-features -- -D warnings
$ cargo test
```

Tests that reach outside the repository sit behind the `live` feature, so a plain `cargo test` does
not build them.
